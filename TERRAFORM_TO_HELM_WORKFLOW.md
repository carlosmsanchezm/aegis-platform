# Terraform to Helm Deployment Workflow

This document explains how to use Terraform outputs to seamlessly deploy Aegis to your cloud infrastructure.

## 📋 Overview

The workflow has been designed to eliminate manual copying of values between Terraform and Helm. Terraform automatically generates the correct Helm values based on the infrastructure it creates.

```
┌─────────────┐      ┌──────────────────┐      ┌─────────────────┐
│  Terraform  │─────>│  Auto-Generated  │─────>│  Helm Deploy    │
│   Outputs   │      │  Helm Values     │      │  (Cloud)        │
└─────────────┘      └──────────────────┘      └─────────────────┘
```

## 🎯 New Terraform Outputs

### 1. `helm_values_aegis_services`
Auto-generated YAML values for the **aegis-services** chart (control plane/hub). Includes:
- Platform API image repository (from ECR)
- Database connection details (from RDS)
- Proxy configuration
- Ingress hosts (with placeholders for your domain)

### 2. `helm_values_aegis_spoke`
Auto-generated YAML values for the **aegis-spoke** chart (workload cluster). Includes:
- k8s-agent image repository
- Control plane gRPC endpoint
- Proxy ingress host
- Cluster ID

### 3. `db_password_secret_value` (sensitive)
Database password generated by Terraform and stored in AWS Secrets Manager

### 4. `jwt_secret_value` (sensitive)
64-character JWT secret for proxy authentication

### 5. `k8s_secret_commands`
Ready-to-run commands to create Kubernetes secrets from Terraform values

## 🚀 Deployment Workflow

### Step 1: Deploy Infrastructure with Terraform

```bash
cd terraform/

# Initialize and apply Terraform
terraform init
terraform apply

# Verify infrastructure
terraform output cluster_name
terraform output rds_endpoint
```

### Step 2: Generate Helm Values

**Option A: Use the helper script (recommended)**
```bash
cd terraform/
./generate-helm-values.sh
```

This creates:
- `charts/aegis-services/values-cloud-generated.yaml`
- `charts/aegis-spoke/values-cloud-generated.yaml`

**Option B: Manual generation**
```bash
cd terraform/
terraform output -raw helm_values_aegis_services > ../charts/aegis-services/values-cloud-generated.yaml
terraform output -raw helm_values_aegis_spoke > ../charts/aegis-spoke/values-cloud-generated.yaml
```

### Step 3: Update Domain Names

The generated files contain `yourdomain.com` placeholders. Update them:

```bash
# For aegis-services
sed -i '' 's/yourdomain.com/your-actual-domain.com/g' \
  charts/aegis-services/values-cloud-generated.yaml

# For aegis-spoke
sed -i '' 's/yourdomain.com/your-actual-domain.com/g' \
  charts/aegis-spoke/values-cloud-generated.yaml
```

Or manually edit the files and replace:
- `platform-api.yourdomain.com` → `platform-api.your-actual-domain.com`
- `platform-api-grpc.yourdomain.com` → `platform-api-grpc.your-actual-domain.com`
- `proxy.yourdomain.com` → `proxy.your-actual-domain.com`

### Step 4: Configure kubectl

```bash
# Get the command from Terraform output
terraform output -raw kubectl_config_command

# Run the command (example):
aws eks update-kubeconfig --region us-east-1 --name aegis-spoke-prod --profile myclaude

# Verify
kubectl get nodes
```

### Step 5: Create Kubernetes Secrets

```bash
cd terraform/

# Create secrets from Terraform-generated passwords
kubectl create secret generic aegis-platform-secrets \
  --from-literal=db-password="$(terraform output -raw db_password_secret_value)" \
  --from-literal=proxy-jwt-secret="$(terraform output -raw jwt_secret_value)" \
  --namespace aegis-system --create-namespace

# Verify
kubectl get secrets -n aegis-system
```

### Step 6: Deploy with Helm

```bash
cd charts/

# Deploy aegis-services (control plane / hub)
helm upgrade --install aegis-services ./aegis-services \
  -f ./aegis-services/values-cloud.yaml \
  -f ./aegis-services/values-cloud-generated.yaml \
  --namespace aegis-system --create-namespace

# Verify deployment
kubectl get pods -n aegis-system

# Deploy aegis-spoke (workload cluster)
helm upgrade --install aegis-spoke ./aegis-spoke \
  -f ./aegis-spoke/values-cloud.yaml \
  -f ./aegis-spoke/values-cloud-generated.yaml \
  --namespace aegis-system

# Verify deployment
kubectl get pods -n aegis-system
```

## 📊 Values File Structure

### Base Values (values-cloud.yaml)
- Static configuration
- Production settings (replicas, resources, security contexts)
- Ingress configuration
- Probe settings
- Affinity rules

### Generated Values (values-cloud-generated.yaml)
- Dynamic values from Terraform
- ECR image repositories
- Database connection details
- Cluster-specific IDs
- AWS-specific configurations

### Merge Strategy
Helm merges these files with later files taking precedence:
1. `values.yaml` (chart defaults)
2. `values-cloud.yaml` (base cloud config)
3. `values-cloud-generated.yaml` (terraform-generated, overrides base)

## 🔐 Security Best Practices

### Sensitive Values
- **DB Password**: Never commit to git, stored in AWS Secrets Manager
- **JWT Secret**: Never commit to git, stored in AWS Secrets Manager
- Generated values files: Safe to commit (no sensitive data)

### Terraform State
- Contains sensitive outputs
- Store in S3 with encryption enabled
- Never commit `terraform.tfstate` to git

### Alternative: External Secrets Operator
Instead of creating K8s secrets manually, use External Secrets Operator:

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: aegis-platform-secrets
  namespace: aegis-system
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: aws-secrets-manager
    kind: SecretStore
  target:
    name: aegis-platform-secrets
  data:
    - secretKey: db-password
      remoteRef:
        key: aegis/prod/db-password
    - secretKey: proxy-jwt-secret
      remoteRef:
        key: aegis/prod/proxy-jwt-secret
```

## 🔄 Update Workflow

When infrastructure changes:

```bash
# 1. Update Terraform
cd terraform/
terraform apply

# 2. Regenerate Helm values
./generate-helm-values.sh

# 3. Update domain names (if needed)
sed -i '' 's/yourdomain.com/your-actual-domain.com/g' \
  ../charts/aegis-services/values-cloud-generated.yaml

# 4. Upgrade Helm deployment
cd ../charts/
helm upgrade aegis-services ./aegis-services \
  -f ./aegis-services/values-cloud.yaml \
  -f ./aegis-services/values-cloud-generated.yaml \
  --namespace aegis-system
```

## 🎯 Benefits

1. **No Manual Copying**: All values automatically synced from Terraform
2. **Type Safety**: Terraform validates values before they reach Helm
3. **Single Source of Truth**: Infrastructure state in Terraform, config in generated files
4. **Easy Updates**: Re-run script when infrastructure changes
5. **Consistency**: Same values between Terraform outputs and Helm values

## 📝 Checklist

Before deploying to cloud:

- [ ] Terraform applied successfully
- [ ] `generate-helm-values.sh` executed
- [ ] Domain names updated in generated files
- [ ] kubectl configured for EKS cluster
- [ ] Kubernetes secrets created
- [ ] NGINX Ingress Controller installed
- [ ] DNS records pointing to ingress
- [ ] TLS certificates configured (cert-manager or manual)
- [ ] Review resource limits in values-cloud.yaml
- [ ] Set appropriate image tags (not `latest`)

## 🆘 Troubleshooting

### Issue: "terraform output not found"
**Solution**: Ensure Terraform has been applied: `terraform apply`

### Issue: Generated values have wrong values
**Solution**: Check Terraform state: `terraform show`

### Issue: Secrets not found in K8s
**Solution**: Verify secret creation:
```bash
kubectl get secrets -n aegis-system
kubectl describe secret aegis-platform-secrets -n aegis-system
```

### Issue: Platform API can't connect to database
**Solution**: Verify database endpoint and credentials:
```bash
terraform output rds_endpoint
kubectl logs -n aegis-system -l app.kubernetes.io/component=platform-api
```
