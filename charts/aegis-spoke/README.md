# Aegis Spoke Helm Chart

A unified Helm chart for deploying Aegis spoke components (k8s-agent and proxy) in workload clusters.

## Overview

This chart deploys the "spoke" side of the Aegis hub-and-spoke architecture:
- **K8s Agent**: Operator that reconciles AegisWorkload CRs and manages Kubernetes Jobs
- **Proxy**: Optional per-cluster proxy for direct workload access (can also use centralized proxy from aegis-services)

The k8s-agent connects back to the central platform-api (hub) to report capacity and receive workload assignments.

## Quick Start

### Local Development

For local development with Docker Desktop (agent only, using centralized proxy):

```bash
# Install with local configuration (proxy disabled)
helm install aegis-spoke ./charts/aegis-spoke \
  -f ./charts/aegis-spoke/values.yaml \
  -f ./charts/aegis-spoke/values-local.yaml \
  --namespace aegis-system --create-namespace
```

### Cloud Deployment

For production deployment on cloud platforms:

```bash
# Install with cloud configuration
helm install aegis-spoke ./charts/aegis-spoke \
  -f ./charts/aegis-spoke/values.yaml \
  --set-string k8sAgent.env.AEGIS_CLUSTER_ID="prod-cluster-1" \
  --set-string k8sAgent.env.AEGIS_CP_GRPC="platform-api-grpc.aegist.dev:8081" \
  --set-string k8sAgent.env.AEGIS_REGION="us-east-1" \
  --set-string k8sAgent.env.AEGIS_PROVIDER="aws" \
  --set-string k8sAgent.env.AEGIS_FLAVORS="cpu-small,cpu-large,gpu-a100" \
  --set-string proxy.jwtSecret="your-jwt-secret-32-chars-min" \
  --set-file proxy.tls.cert=/path/to/cert.pem \
  --set-file proxy.tls.key=/path/to/key.pem \
  --namespace aegis-system --create-namespace
```

## Configuration

### Component Control

You can enable or disable individual components:

```yaml
# Deploy k8s-agent only (use centralized proxy)
k8sAgent:
  enabled: true  # implicitly enabled
proxy:
  enabled: false

# Deploy both k8s-agent and per-cluster proxy
k8sAgent:
  enabled: true
proxy:
  enabled: true
```

### Environment-Specific Values

The chart includes layered values files:

1. **`values.yaml`** – Base defaults for all environments
2. **`values-local.yaml`** – Local development overrides (proxy disabled)
3. **`values-local-tls.yaml`** – Local TLS connection settings
4. **`values-cloud-tls.yaml`** – Cloud TLS connection settings
5. **`values-cloud-generated.yaml`** – Auto-generated by Terraform (gitignored)

## K8s Agent Configuration

### Basic Configuration

```yaml
k8sAgent:
  replicaCount: 1

  image:
    repository: carlosmsanchez/aegis-k8s-agent
    tag: "latest"
    pullPolicy: IfNotPresent
```

### Hub Connection Settings

Configure how the agent connects to the central platform-api:

```yaml
k8sAgent:
  env:
    # Hub gRPC endpoint
    AEGIS_CP_GRPC: "platform-api-grpc.aegist.dev:8081"

    # Cluster identifier (must be unique across all clusters)
    AEGIS_CLUSTER_ID: "prod-cluster-1"

    # TLS settings (for secure connection to hub)
    AEGIS_CP_GRPC_INSECURE: "true"  # Set to "false" for TLS
    AEGIS_CP_GRPC_SKIP_VERIFY: "false"  # Set to "true" for self-signed certs
```

### Geographic and Capacity Metadata

The agent reports metadata to help the platform make placement decisions:

```yaml
k8sAgent:
  env:
    # Geographic location
    AEGIS_REGION: "us-east-1"  # AWS region or equivalent
    AEGIS_PROVIDER: "aws"      # Cloud provider (aws, gcp, azure, on-prem)

    # Available compute flavors
    # Comma-separated list that platform-api uses for workload placement
    AEGIS_FLAVORS: "cpu-small,cpu-large,gpu-a100,gpu-h100"
```

**Common flavor naming conventions:**
- `cpu-small` - 2 vCPU, 4GB RAM
- `cpu-medium` - 4 vCPU, 8GB RAM
- `cpu-large` - 8 vCPU, 16GB RAM
- `gpu-a100` - 8 vCPU, 32GB RAM, 1x A100 GPU
- `gpu-h100` - 16 vCPU, 64GB RAM, 1x H100 GPU

### Proxy Integration

Configure the proxy endpoint that workloads will use:

```yaml
k8sAgent:
  env:
    # Proxy hostname for workload access
    # Can point to centralized proxy (aegis-services) or per-cluster proxy
    AEGIS_PROXY_INGRESS_HOST: "proxy.customer-a.aegis.dev"
```

## Proxy Configuration

### Basic Configuration

```yaml
proxy:
  enabled: true  # Set to false to use centralized proxy
  replicaCount: 1

  image:
    repository: carlosmsanchez/aegis-proxy
    tag: "latest"
    pullPolicy: IfNotPresent

  service:
    type: ClusterIP
    port: 8085
```

### JWT Authentication

The proxy validates JWT tokens for workload access:

```yaml
proxy:
  # JWT signing secret (must match platform-api's JWT_SECRET)
  # Minimum 32 characters for security
  jwtSecret: "your-jwt-secret-32-chars-minimum"
```

### Ingress Configuration

```yaml
proxy:
  ingress:
    enabled: true
    className: "nginx"

    # Public hostname for proxy access
    # Examples:
    #   Local: "proxy.localtest.me" or "proxy.127.0.0.1.nip.io"
    #   Cloud: "proxy.customer-a.aegis.dev"
    hostname: "proxy.yourdomain.com"

    annotations:
      cert-manager.io/cluster-issuer: "letsencrypt-prod"
      nginx.ingress.kubernetes.io/backend-protocol: "HTTP"
```

### TLS Configuration

```yaml
proxy:
  tls:
    # Terminate TLS at ingress controller or at proxy?
    terminateAtIngress: true  # Most common for cloud deployments

    # Certificate and key (required if terminateAtIngress: false)
    cert: ""  # Set via --set-file proxy.tls.cert=/path/to/cert
    key: ""   # Set via --set-file proxy.tls.key=/path/to/key
```

### Client Certificate Validation

For enhanced security, validate client certificates:

```yaml
proxy:
  clientCerts:
    enabled: true
    # Only allow clients with SANs matching these suffixes
    sanSuffixes:
      - ".aegis.dev"
      - ".internal.company.com"
```

## Security Configuration

### RBAC

The k8s-agent requires cluster-wide permissions to manage workloads:

```yaml
rbac:
  create: true  # Create ClusterRole and ClusterRoleBinding
  serviceAccount:
    create: true
    name: "aegis-k8s-agent"
```

**Permissions granted:**
- **AegisWorkload CRD**: Full access (create, read, update, delete, watch)
- **Jobs**: Full access (for workload execution)
- **Pods**: Read access (for status reporting)
- **Namespaces**: Read access (for multi-tenant support)

### Pod Security Context

```yaml
k8sAgent:
  securityContext:
    runAsNonRoot: true
    runAsUser: 65532
    fsGroup: 65532

  containerSecurityContext:
    allowPrivilegeEscalation: false
    capabilities:
      drop: [ALL]
    readOnlyRootFilesystem: true
    runAsNonRoot: true
    runAsUser: 65532
```

## Troubleshooting

### Check Deployment Status

```bash
# Check all spoke resources
kubectl get all -l app.kubernetes.io/instance=aegis-spoke -n aegis-system

# Check k8s-agent specifically
kubectl get pods -l app.kubernetes.io/component=k8s-agent -n aegis-system
kubectl logs -l app.kubernetes.io/component=k8s-agent -n aegis-system

# Check proxy (if enabled)
kubectl get pods -l app.kubernetes.io/component=proxy -n aegis-system
kubectl logs -l app.kubernetes.io/component=proxy -n aegis-system
```

### Verify Hub Connection

```bash
# Check if k8s-agent can connect to platform-api
kubectl logs -l app.kubernetes.io/component=k8s-agent -n aegis-system | grep "connected to platform-api"

# Check for gRPC connection errors
kubectl logs -l app.kubernetes.io/component=k8s-agent -n aegis-system | grep -i "grpc"
kubectl logs -l app.kubernetes.io/component=k8s-agent -n aegis-system | grep -i "connection refused"
```

### Check AegisWorkload CRDs

```bash
# Verify CRD is installed
kubectl get crd aegisworkloads.aegis.dev

# List workloads in cluster
kubectl get aegisworkloads -A

# Describe a specific workload
kubectl describe aegisworkload <workload-name> -n <namespace>
```

### Common Issues

1. **Agent can't connect to hub**
   - Verify `AEGIS_CP_GRPC` endpoint is reachable
   - Check TLS settings match hub configuration
   - Verify network policies allow egress to hub

2. **Workloads not being scheduled**
   - Check `AEGIS_FLAVORS` matches workload requirements
   - Verify agent is registered with hub: check platform-api logs
   - Check cluster capacity: `kubectl describe nodes`

3. **Proxy ingress not accessible**
   - Verify ingress controller is installed
   - Check DNS resolution for `proxy.ingress.hostname`
   - Verify TLS certificates are valid

4. **RBAC permission errors**
   - Ensure `rbac.create: true`
   - Verify ServiceAccount is created
   - Check ClusterRoleBinding: `kubectl get clusterrolebinding -l app.kubernetes.io/instance=aegis-spoke`

## Architecture Notes

### Hub-and-Spoke Model

- **Hub (aegis-services)**: Central control plane with platform-api
  - Receives workload requests from users
  - Makes placement decisions based on flavors/capacity
  - Creates AegisWorkload CRs in target clusters

- **Spoke (aegis-spoke)**: Agent deployed per workload cluster
  - Reports capacity and available flavors to hub
  - Watches for AegisWorkload CRs
  - Creates and manages Kubernetes Jobs
  - Reports workload status back to hub

### Proxy Deployment Options

**Option 1: Centralized Proxy (Recommended for most cases)**
- Deploy proxy once in aegis-services (hub)
- All spokes connect workloads to central proxy
- Simpler management, fewer ingress points

```yaml
# aegis-spoke configuration
proxy:
  enabled: false
k8sAgent:
  env:
    AEGIS_PROXY_INGRESS_HOST: "proxy.central.aegist.dev"
```

**Option 2: Per-Cluster Proxy**
- Deploy proxy in each spoke cluster
- Each cluster has its own ingress endpoint
- Better for multi-tenant or isolated environments

```yaml
# aegis-spoke configuration
proxy:
  enabled: true
  ingress:
    hostname: "proxy.cluster-1.aegist.dev"
```
