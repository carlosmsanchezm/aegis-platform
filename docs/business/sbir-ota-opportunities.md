## Detailed Opportunity Analysis

### 1. Kessel Run DevSecOps CSO (FA8730-22-S-C001) — Fit Score: 5/5

**SAM.gov verified**: Active, response date November 29, 2027. Special Notice type, updated Nov 20, 2025.

**Why Aegis fits:** Kessel Run is the Air Force's premier software factory, the same organization that pioneered agile DevSecOps in DoD. Their CSO explicitly seeks "innovative approaches to product and service offerings in the Software and DevSecOps realm." Aegis is a DevSecOps platform for GPU workload orchestration — it schedules workloads across Kubernetes clusters while enforcing compliance controls. The hub-and-spoke architecture, Helm chart deployment model, and Iron Bank-ready images align directly with Kessel Run's software supply chain approach.

**What to submit:** A short solution brief (typically 5-10 pages) describing Aegis as a "GPU workspace platform that gives AF data scientists VS Code on GPU hardware inside their ATO boundary in 90 seconds, with built-in NIST 800-53 controls, budget enforcement, and audit logging."

**Technical Approach (Draft):**

Aegis Platform addresses a critical gap in the Air Force DevSecOps ecosystem: GPU workload orchestration with compliance controls. While Kessel Run and Platform One have revolutionized how the AF builds and deploys software, ML/AI teams still struggle with GPU access — assembling multi-account AWS architectures that take 3-6 months and provide degraded developer experience through browser-based IDEs on remote desktops.

Aegis replaces this with a Helm chart deployment that gives data scientists native VS Code on GPU hardware in under 90 seconds. The hub-and-spoke Kubernetes architecture runs the Platform API (Go/gRPC), Keycloak OIDC, and reverse proxy on a hub cluster, while lightweight spoke agents on GPU clusters heartbeat outbound — no inbound firewall rules required. The placement algorithm selects optimal clusters based on GPU availability and time-to-first-GPU metrics. Built-in security: fail-closed RBAC, single-use JWT sessions (5-min TTL, JTI enforcement), structured audit logging, default-deny network policies, and per-project budget enforcement.

Phase I prototype would deploy Aegis alongside Kessel Run's existing toolchain, demonstrate <90s workspace launch with AF data scientists, generate OSCAL evidence packages, and produce Iron Bank-approved container images. The existing working prototype on EKS demonstrates TRL 6+ maturity with multi-cluster scheduling, workspace launching, budget enforcement, and compliance controls already operational.

## SAM.gov API Configuration

API key: `SAM-5ba85c57-2e2a-454f-9cd0-80fa44db34be`
Daily quota: **~10 requests/day** (free tier). Resets at midnight UTC.

**Correct v2 search endpoint (verified 2026-03-22):**
```
GET https://api.sam.gov/opportunities/v2/search
  ?api_key=SAM-...
  &postedFrom=06/01/2025              # MM/DD/YYYY format (NOT YYYY-MM-DD)
  &postedTo=03/22/2026               # Max range: 1 year
  &title=DevSecOps                    # USE THIS — filters by title (works)
  &size=25
  &noticeType=o,s,p,k                # o=solicitation, p=presol, k=combined, s=special
  &sortBy=-modifiedOn
```

**Key findings from API testing:**
- Date format: **`MM/DD/YYYY`** (not YYYY-MM-DD — docs are misleading)
- Date range: **must be ≤1 year apart** or returns error
- `title` parameter: **WORKS** — filters results by title text
- `keyword` parameter: **DOES NOT FILTER** — returns all ~35K results regardless of keyword value
- `solNumber` parameter: works for exact solicitation number lookup
- `noticeType`: comma-separated codes (o=solicitation, p=presolicitation, k=combined, r=sources sought, s=special)
- `size`: results per page, default 10
- `sortBy`: `-modifiedOn` for most recent first
- Free tier quota: **~10 requests per day** — budget API calls carefully
- **Best strategy**: Use browser SAM.gov for broad discovery, API for specific lookups
