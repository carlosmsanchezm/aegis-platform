# Make Commands Quick Reference

This guide summarizes the most common `make` targets in the repository so you don’t have to read the full Makefile every time. Run commands from the repo root unless noted.

## Global / Root Makefile

| Target | Description |
|--------|-------------|
| `make install-tools` | Install global tooling (kubebuilder, controller-gen, golangci-lint, etc.). |
| `make gofmt` | Format Go sources using `gofmt`. |
| `make golangci-lint` | Run Go linters via golangci-lint. |
| `make test` | Execute Go unit tests for all modules. |
| `make docker-build SERVICES="platform-api proxy"` | Build Docker images (the `SERVICES` variable can be adjusted). |
| `make docker-push SERVICES="platform-api"` | Push Docker images to the configured registry. |
| `make workspace-image` | Build the workspace VS Code image. |
| `make workspace-image-push` | Push the workspace image to the registry. |
| `make preview` | Run the full preview workflow locally (terraform + helm + smoke tests). |
| `make ecr-login` | Authenticate Docker to AWS ECR (`AWS_PROFILE=aegis-new`). |
| `make push-cloud-images` | Build + push all 4 service images to ECR with `CLOUD_IMAGE_TAG` (default: git SHA). |
| `make deploy-cloud` | Deploy hub to cloud EKS (runs `generate-cloud-deployment.sh --non-interactive`). Images must already be in ECR. |
| `make deploy-cloud-full` | One-shot cloud deploy: ECR login + push images + terraform apply + full deploy (Steps 1-9). |
| `make build-ui-cloud` | Build aegis-ui Docker image for linux/amd64. |
| `make push-ui-cloud` | Build + push aegis-ui image to ECR. |
| `make build-local-all` | Build all 3 service images for local Docker Desktop (native arch). |
| `make build-platform-local` | Build platform-api image for local Docker Desktop. |
| `make build-proxy-local` | Build proxy image for local Docker Desktop. |
| `make build-agent-local` | Build k8s-agent image for local Docker Desktop. |
| `make preview-clean` | Tear down the preview infrastructure locally. |
| `make rerun-preview-failures` | Rerun only the failed jobs from the latest preview GitHub Actions run. If the workflow definition changed, it automatically dispatches a `tests-only` run using the current workflow (see `scripts/rerun-preview-failures.sh`). |

## agents/k8s-agent

Change directory (`cd agents/k8s-agent`) before running these.

| Target | Description |
|--------|-------------|
| `make generate` | Regenerate deep-copies, manifests, and CRDs via controller-gen. |
| `make fmt` | Format Go sources in the agent module. |
| `make vet` | Run `go vet` on the agent module. |
| `make test` | Run unit tests for the agent. |
| `make docker-build` | Build the k8s-agent controller image. |
| `make docker-push` | Push the k8s-agent image. |
| `make install` | Install CRDs into the current cluster (uses controller-gen output). |
| `make deploy` | Deploy the k8s-agent controller to the cluster. |
| `make undeploy` | Remove the k8s-agent controller from the cluster. |
| `make test-e2e` | Run the agent’s end-to-end test suite (`agents/k8s-agent/test/e2e`). |

## services/platform-api

Change directory (`cd services/platform-api`) before executing these targets.

| Target | Description |
|--------|-------------|
| `make fmt` | Format Go code for the platform API. |
| `make vet` | Run `go vet` for the platform API. |
| `make test` | Run unit tests. |
| `make docker-build` | Build the platform API image. |
| `make docker-push` | Push the platform API image. |

## charts

Within `charts/aegis-services` or `charts/aegis-spoke` you’ll find Helm values and helper scripts; the root Makefile provides wrapper targets:

| Target | Description |
|--------|-------------|
| `make helm-lint` | Run `helm lint` on core charts. |
| `make helm-template` | Render Helm templates for quick inspection. |

## scripts

While not Make targets, these scripts are often invoked by the Makefile or CI:

- `./scripts/test-local-with-tls.sh` – Local smoke test against the platform API + workspace.
- `./scripts/test-workspace-connection.sh` – Workspace VS Code connectivity smoke test.
- `./scripts/test-workspace-crd.sh` – Validates new workspace CRDs.
- `./scripts/rerun-preview-failures.sh` – Uses the GitHub CLI to rerun only failed jobs from a preview workflow run. If the failing run predates the current workflow changes, it dispatches a new `tests-only` run. Customize behaviour with `WORKFLOW_FILE`, `RUN_ID`, `BRANCH`, `RUN_SUBSET`, `SUITES`, and `WATCH`.

## Tips

1. Run `make help` (where available) to see autogenerated docs for a sub-module.
2. When a command needs to run inside a subdirectory (`agents/k8s-agent`, `services/platform-api`), change directories first.
3. CI uses docker-based targets (`make docker-build`, `make docker-push`) – make sure you’re logged into the correct registry (AWS ECR).
4. The preview workflow (`make preview`) mirrors the GitHub Actions job: Terraform apply → Helm deploy → E2E tests.
5. Use `make <target> -n` (dry run) to see what a target would execute without running it.

For exact details or additional targets, inspect the corresponding Makefile in each module.
